## Что исправлено

- HTTP predict публикует итог только после полного успешного прохода, проверяет
  hash/order/labels/Unicode bounds и не посылает gold в сервис. При сбое — failure.json.
- Predict, eval и benchmark защищены от случайного затирания предыдущих результатов.
- Eval требует явную gold-разметку; отсутствие `entities` не означает пустую разметку.
  Предсказания за пределами исходной строки отклоняются до выдачи метрики.
- Benchmark работает с CPU-only клиентом, явно отличает его оборудование от сервера;
  обязательный NVML-замер не может незаметно стать отсутствующим/нулевым.
  Проверяются пустой input, NaN/inf load rate, malformed HTTP и повторяемость spans.
- Smoke-output никогда не публикуется в MLflow/общую сводку, даже без числовых лимитов.
  Общие проверки запроса обучения вынесены в `training/request_config.py`.
- Train/dev проверяются на наличие разметки, непустоту и пересечение hash до загрузки
  модели; пустые окна дают понятную ошибку. Отдельный final-fit train+dev не переписан.
- Official wrapper учитывает smoke max-epochs; запрещённый resume не создаёт каталоги.
- При сбое переименования checkpoint возвращается прежний каталог. Необработанная
  `.backup` не удаляется следующим сохранением, а требует проверки пользователем.
- Подготовка bundle заранее проверяет наличие весов/metadata/reference и непустого train.
- Исправлен research fallback при частичной установке pyahocorasick/rapidfuzz;
  тест квоты отделён от независимого fuzzy-дедупликатора.
- Coverage subprocess получает тот же branch/config режим при смене cwd:
  устранён `Can't combine branch coverage data with statement data`.

Тесты native TensorRT API содержат дублёры для ошибок hash/version/profile/binding;
их прохождение само по себе не доказывает GPU parity. Для этого ниже — полный
реальный HTTP-прогон, а не только unit-моки.

## Контрольный HTTP benchmark

**A100 80 GB PCIe**, driver **580.173.02**, CPU Intel Xeon / 20 vCPU;
конкретный `lscpu` сохранён в сыром summary. Сервер и клиент на одном хосте,
loopback HTTP, без параллельного обучения. Default TensorRT BF16 s33+s31,
PyTorch BF16 s21, CPU TorchScript CRF, window_batch=16.

| Условие/метрика | Значение |
|---|---:|
| Dev | 1 500 исходных документов, без изменения gold |
| HTTP batch / concurrency / rounds | 8 / 1 / 2 |
| Обработано | 3 000 сообщений, 376 запросов |
| Warmup | 3 запроса, вне тайминга; загрузка модели также исключена |
| Время / throughput | 47,503 с / **63,153 сообщения/с** |
| Latency mean / p50 / p95 / p99 / max | 126,25 / 93,50 / **299,60** / 567,68 / 703,42 мс |
| NVML device-used peak | 6 411,125 MiB ≈ **6,26 GiB**, 474 пробы по 100 мс |
| Dev exact micro-F1 | **0,9174098488**; TP 7 098, FP 678, FN 600 |
| Повторяемость / parity с предыдущим predict | **0 изменённых документов / spans** |
| HTTP errors | **0** |

Это контроль воспроизводимости команд, **не новый прирост модели или новая оценка
привата**. Предыдущие performance-замеры не заменялись лучшим числом из повторов.
Все пред-/постобработки, словарь и повторы входят в HTTP-тайминг. NVML — наблюдаемый
пик полного device-used, не универсальная гарантия для произвольного размера входа.
