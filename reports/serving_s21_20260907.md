# s21 TensorRT BF16 — отдельная оптимизация 07.09.2026

Рецепт s62+c02, веса, словарь, пороги, окна и decoder не менялись.
Заменён только encoder s21: PyTorch BF16 → TensorRT 10.3 BF16.
После проверки основной сервис переключён на `a100-s21`.
Прежний контейнер сохранён как `uzner-serving-a100-hybrid-backup-20260907`;
готовый архив `a100-final` не перезаписывался.

## Экспорт

Штатный ONNX экспорт создал условный `If_2161`: ветви относительных позиций
возвращали ранги 3 и 4, что отклонил TensorRT. В отдельном процессе экспорта
`build_rpos` специализирован для encoder self-attention: query/key имеют
одинаковую длину, поэтому результатом всегда являются исходные `relative_pos`.
Cross-attention запрещён. После экспорта helper Transformers восстанавливается.
Это не отключение relative attention и не изменение обученных весов.

Проверены длины 2/7/32/128/257/512, batch 1/2/3/8/16, padding, формы и
конечность GPU-результатов. Hidden states не побитно равны BF16 PyTorch;
критерий приёмки — полный exact-span dev и измеренное ускорение.
Сборка engine после ONNX: **41,60 с**, размер около **567 MiB**.

SHA-256 engine: `040032673f01fa06a6f07c81df9acfef80bc22ed8b7fecf84a94935aceb069ca`.
SHA-256 ONNX: `1f1de61e441765e75cf4979666e5f1fc3a56d64e34e9341dc9cef5eced282499`.

## Сравнение

A100 80GB PCIe, driver 580.173.02, CUDA 12.4, PyTorch 2.6.0,
Transformers 5.14.1, TensorRT 10.3.0. По одному Uvicorn worker на сервис.
Два резидентных сервиса, benchmark строго последовательно, без обучения.
HTTP: batch=1, concurrency=1, 2 полных прохода, 3 warmup-запроса вне измерения.
Все пред- и постобработка включены; кэш ответов отсутствует.

## Воспроизведение и откат

Нужны исходный bundle, прежние s33/s31 plans и новый `s21.plan` с `s21.json`
в `artifacts/serving/engines-bf16/`. Новый граф экспортировать в свежий ONNX-каталог:
старый ошибочный ONNX нельзя переиспользовать.

```bash
uv run --extra export python scripts/export_service.py \
  --models s21 --precision bf16 --output artifacts/serving/engines-bf16
docker build --build-arg RUNTIME_PROFILE=configs/serving/trt_all_bf16.json \
  -t ner-uz-solution:a100-s21 .
docker run --rm --gpus all -p 8000:8000 ner-uz-solution:a100-s21
```

Default теперь совпадает с новым профилем. Откат при сборке:
`--build-arg RUNTIME_PROFILE=configs/serving/hybrid_bf16.json`.
Новый образ не требует env/mounts:
выбранный профиль копируется в default при сборке.
Существующий локальный Docker-архив содержит старый вариант, а не новый engine.
Полные исходные измерения: `artifacts/serving/benchmarks/s21-fast-*/`.
