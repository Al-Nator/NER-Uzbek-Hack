## Данные и честность сравнения

- Все 13 000 официальных train-документов сохранены без изменений.
- Добавлены только изменённые тексты со статусом `ok`; `review`/ошибки исключены.
- Общий ключ — `(source_hash, direction)`. После фильтра статусов общих ключей
  4 813; парное исключение 10 дублей/совпадений оставляет **4 803 для каждого метода**.
- Ключи и их порядок одинаковы. Это 4 606 исходных документов:
  1 758 копий Latin→Cyrillic и 3 045 Cyrillic→Latin.
- Дедупликация по `normalize_surface(text)` (регистр, пробелы, варианты апострофов)
  внутри метода, относительно original train и dev. Если хотя бы одна сторона
  пары исключается, исключается и другая. Сам текст для обучения не нормализуется.
- Dev — исходные 1 500 документов. Для удаления совпадений использованы его тексты,
  не метки. Никакого нового разбиения нет; при будущем разбиении оригинал и копии
  нужно объединять по `source_hash`.
- Метки и offsets структурно проверены; **языковое качество не утверждено**.
  Поэтому прирост от аугментаций — гипотеза, а не ожидаемый гарантированный результат.

Неизменяемый релиз: `artifacts/series4/transliteration_v1/`:
`converter_matched.jsonl`, `luna_matched.jsonl`, `manifest.json`.
Manifest содержит SHA-256 всех шести входных файлов, результатов и счётчики отбора.
`converter_full.jsonl` — только подготовленный локальный вариант, не часть очереди.
Provenance в каждой копии: `source_hash`, `direction`, `method`, `input_hash`;
у копии отдельный стабильный `hash`. Raw-файлы не изменяются.

Подготовка воспроизводится [`prepare_transliteration_series.py`](../scripts/prepare_transliteration_series.py)
с `--derived` на каталог исходных четырёх JSONL и `--output` на **новый** каталог;
существующий релиз скрипт отказывается перезаписывать.

## Рецептура

Reference — [s32](THIRD_SERIES.md#перенос-globalpointer-на-bge--s32), F1 0.90595.
Оба опыта начинают заново с одинакового pretrained `BAAI/bge-m3-retromae`,
revision `95c4f81ef8f7911dcac8e384532489c32c8dea64`, не с NER-checkpoint s32/s33.

GlobalPointer с RoPE, head size 64, threshold 0.5; context 512, overlap 128.
Seed 42, до пяти эпох, patience 2, train/eval batch 8, accumulation 1,
AdamW LR 2e-5, weight decay 0.01, warmup 10%, gradient clipping 1.0,
BF16 autocast, без gradient checkpointing. Остальное совпадает с s32.
Best выбирается по exact-span micro-F1, last сохраняется для resume.

Сравнение методов контролирует исходные документы, направления, количество копий,
модель, seed и рецептуру. Токенизация немного различается: 20 297 против 20 283
окон, 2 538 против 2 536 batch/эпоху. Это не строго равный бюджет tokens/steps.
Относительно s32 расширение train также увеличивает вычисления на эпоху;
результат нельзя интерпретировать как абляцию при фиксированном compute.

## Проверки

Локально проверены хэши всех входов и выходов, одинаковый порядок пар и загрузка
обоих train/dev через обычный data loader. Удалённые хэши обоих наборов и official
train/dev совпадают с локальными.

Полный preflight на A100-хосте построил окна и span targets для обеих конфигураций:

| Split | Документы | Окна s40 / s41 | Представимые сущности / gold |
|---|---:|---:|---:|
| train | 17 803 | 20 297 / 20 283 | 86 761 / 86 779 |
| dev | 1 500 | 1 682 / 1 682 | 7 697 / 7 698 |

Не все символьные spans представимы токенизатором: 18 train и 1 dev не покрыты.
Это диагностическое ограничение, не основание менять dev или его gold-метки.
Тесты отбора проверяют provenance, alignment, offsets, исключение review/неизменённых
текстов, парную дедупликацию, защиту от перезаписи и идентичность рецептур s32.
Smoke/unit-результаты в MLflow не публикуются.

Финальная выборочная suite: **76 passed**, Ruff check/format и `git diff --check`
без ошибок. Проверены также окна, BIO/BIOES, метрики, доменный контракт,
MLflow tracking/transfer и удалённый workflow. Это не запуск всей workspace-suite.
На s40 подтверждены реальные optimizer steps и поступление loss/LR в MLflow.
Измеренное время: **32.84 / 32.96 минуты** от первого до последнего events каждого
run, без отдельного времени возврата checkpoint-ов.

## Логи и возврат

Очередь уже запущена; повторять `start` с этими run ID не нужно.
Подключение к живому терминалу:

```bash
ssh -t alnator zellij attach uzner-s40-s41
```

Live MLflow: [localhost:5001](http://127.0.0.1:5001), experiment
`uzner-fourth-series-a100` ([runs](http://127.0.0.1:5001/#/experiments/3/runs)).
SSH tunnel обслуживает локальный
`uzner-mlflow-s4-tunnel.service`. Подробные train loss/LR/gradient norm пишутся
каждые 25 шагов; dev-метрики появляются после evaluation эпохи.

На alnator результаты лежат в `/home/danya/NER-Uzbek-Hack/runs/<run_id>/`:
`logs/events.jsonl`, `logs/history.csv`, `logs/console.log`, `metrics/`,
`predictions/`, `resolved_config.yaml`, `environment/`, `checkpoints/`.
Resolved config и data hashes фиксируют фактически использованный набор.

Локальный `uzner-return-s40-s41.service` ждёт каждый завершённый run, затем
возвращает весь каталог через rsync, проверяет SHA-256 и импортирует метрики,
params/tags и лёгкие артефакты в основной MLflow на [localhost:5000](http://127.0.0.1:5000),
experiment `uzner-first-series`. Checkpoint-ы в MLflow не дублируются.
Локальный компьютер должен оставаться включённым для автоматического возврата.
Отключение локального компьютера не прерывает обучение в zellij.

```bash
journalctl --user -u uzner-return-s40-s41 -f
```

После перезагрузки локального компьютера или для ручного возврата:

```bash
uv run python scripts/remote_experiments.py watch \
  --series configs/series/fourth_a100.yaml --stage all \
  --run-suffix s4-translit-matched-v1
```

Если SSH tunnel не поднят: `uv run python scripts/remote_experiments.py tunnel`.
Возврат тяжёлых best/last checkpoint-ов занимает дополнительное время после обучения.
