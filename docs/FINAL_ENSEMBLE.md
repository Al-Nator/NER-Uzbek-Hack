## Рецепт

Повторяется **s62**, подтверждённый public F1 0.8861, а не s70 со сменой BGE
на s45. Новый ансамбль — `f14_s62_train_dev_vote_v1`. Точное большинство 2/3,
три голоса, одинаковые правила offsets, окон и декодирования.

| Стадия | Рецепт | Фиксированный checkpoint |
|---|---|---|
| f10 | s32: pretrained BGE-M3-RetroMAE + GP | Эпоха 5; подготовка BGE, не отдельный голос |
| f11 | s33: low-LR 2e-6 из f10, новый optimizer/scheduler | Эпоха 1 продолжения при scheduler budget 2 эпохи |
| f12 | s21: pretrained mDeBERTa-v3-base + BIOES/CRF | Эпоха 5 |
| f13 | s31: pretrained XLM-R-large + GP | Эпоха 5 |

Голоса: **f11 + f12 + f13**. Первая эпоха продолжения выбрана заранее по
checkpoint исходного s33. Урезать scheduler до одной эпохи нельзя: это изменило
бы LR-траекторию относительно исходной первой эпохи двухэпохового продолжения.

Все стадии используют **13 000 original train + 1 500 бывшего dev = 14 500**.
Silver, Luna, Sol, public test и другие данные не добавляются. Encoder revisions,
512/128, batch/accumulation, LR, seed 42 и BF16 сохранены из resolved configs
исходных компонентов. Early stopping отключён, validation полностью отсутствует.
Никакие новые dev-F1 не вычисляются и не публикуются как независимая оценка.
Это повторное обучение, а не дообучение старых весов только на dev.

## Очередь

Конфиги — `configs/final/f10_*.yaml` ... `f13_*.yaml`.
Стадии типизированы в `src/uzner/training/final_ensemble.py`.
На A100 выполняются последовательно, по отдельному процессу на стадию.

Локальный контроллер `scripts/start_final_ensemble_after_archive.py` сначала
дожидается `artifacts/remote_archive/alnator_20260906_v1/deletion_complete.json`.
Без завершения двух проверок и очистки старых run-копий новое обучение не стартует.
Ошибка архива останавливает контроллер, а не пропускает защиту.

После открытия условия запуска создаётся zellij-сессия `uzner-s62-train-dev-v1`.
Remote MLflow experiment: `uzner-final-fit-a100`, UI localhost:5001.
Ориентир обучения после архива — **2–3 часа** на A100; это оценка по предыдущим
GP/CRF-запускам, не измеренное время нового ансамбля. Копирование идёт отдельно.

```bash
journalctl --user -u uzner-final-ensemble.service -f
ssh -t alnator zellij attach uzner-s62-train-dev-v1
```

Zellij доступен после фактического старта. Состояние локального контроллера:
`artifacts/final_ensemble_queue_v1/status.json`.

## Артефакты

Каждая стадия сохраняет config, source snapshot, data hashes, подробные train
метрики, последнюю модель и optimizer/RNG. `best` — hard-link копия фиксированного
последнего checkpoint, а не подбор по F1; повторная запись run запрещена.
Для f11 сохраняются хэши исходного f10 и факт reset optimizer/scheduler.

На локальную машину автоматически возвращаются метрики и MLflow-история всех
стадий, а для трёх финальных голосов — best inference-веса с проверкой SHA-256.
Из-за ограниченного свободного места optimizer/last и промежуточные веса f10
остаются на A100. `.checkpoint-transfer-pending` честно отмечает неполный перенос
полных resume-checkpoint-ов; `inference_weights_verified.json` подтверждает
проверенный поднабор весов. Новые удалённые checkpoint-ы не удаляются.

По завершении создаётся `runs/f14_s62_train_dev_vote_v1/resolved_config.json`,
совместимый с `scripts/predict_ensemble.py`. Посылки на лидерборд автоматически
не выполняются. Старые s62, s70 и их public-предсказания не меняются.

## Проверки

14 тестов final-fit/ensemble/submission прошли: точный рецепт, три голоса,
включение 14 500 документов, отсутствие dev-метрик, CRF и GP, фиксированные
эпохи, warm-start с reset optimizer, двухэпоховый scheduler при остановке на
первой эпохе и shared best/last без повторной записи.

Проверен запрет старта при незавершённом/ошибочном архивировании. На A100
прошли отдельные GPU smoke для BGE-GP, mDeBERTa-CRF и XLM-R-GP: forward/backward
и сохранение checkpoint, по два документа. Временные checkpoint-ы удалены,
MLflow smoke не создавался. Ruff изменённых модулей и тестов пройден.
