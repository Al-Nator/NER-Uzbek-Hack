## Общий reference

s32: BGE-M3-RetroMAE + GlobalPointer, exact micro-F1 `0.905954`, epoch 5.
Все A100-абляции стартуют с одинакового pretrained checkpoint, **не с NER s32**:
`BAAI/bge-m3-retromae`, revision `95c4f81ef8f7911dcac8e384532489c32c8dea64`.
Official train 13 000, исходный dev 1 500; без транслитераций/MELM/внешних данных.
512/128, GP head size 64, RoPE, threshold .5; seed 42, AdamW 2e-5, warmup .1,
linear decay, weight decay .01, batch 8, accumulation 1, BF16, без gradient checkpointing.
До пяти эпох, patience 2, best по exact-span micro-F1 и last для resume.

s57/s58 используют **best веса s32, полностью замороженные**. Их сравнение —
постобработка одной фиксированной модели, не дополнительные encoder-эпохи.
Не смешиваем новые данные, новые цели и inference-правила в одном первом опыте.

## Цели на A100

**Сглаживание.** [Boundary Smoothing, ACL 2022](https://aclanthology.org/2022.acl-long.490/)
адаптировано к multilabel GP loss: масса ε переносится с положительного span
на допустимые соседние границы Manhattan-radius 1 того же класса. Padding,
игнорируемые пары и другие gold-positive не становятся отрицательными соседями.
Взвешенный logsumexp использует y и 1−y; при ε=0 строго совпадает с исходным GP loss.
Это адаптация функции потерь для GP, не буквальная CE-реплика статьи.
Inference и строгость exact-span метрики остаются прежними.

**Трудные отрицательные.** Поверх обычного GP loss добавлена softplus-цель:
gold-positive, неправильные классы на gold-границах, сдвиги начала/конца на 1–2
токена, top-32 модельных отрицательных пар на окно. Маска берётся только из train:
gold-positive и ignored пары никогда не становятся negatives.
Онлайновые false positives — ошибки текущей модели на train, не добытые из dev.
Это не исправление разметки: ошибки train остаются источником шума.

**Взаимодополняющие головы.** Один encoder forward; GP, BIOES-линейная проекция
+ trainable CRF и отдельные START/END logits дают градиенты общему encoder-у.
CRF NLL нормируется по длине последовательности, boundary BCE — по валидным позициям.
CRF вычисляется пакетно; нечёткие/частичные spans не создают противоречивых целей.
Проверяем каждую auxiliary-голову отдельно, затем их сумму без изменения весов.
На inference **используется только GP**: это проверка разных обучающих сигналов,
не ансамбль трёх декодеров. Слияние кандидатов трёх голов — будущая отдельная абляция,
не скрытое изменение этой очереди. Два дополнительных encoder-forward не нужны.

## Правильная память kNN

`models/memory_knn.py`, `training/memory_pipeline.py`:

- Ключ — контекстный hidden frozen s32; значение — train BIOES-тег, включая `O`.
- Равномерная случайная выборка уникальных token offsets: Bernoulli .06,
  затем равномерный cap 100 000. Нет искусственного выравнивания классов,
  которое превратило бы фоновые запросы в завышенный entity prior.
- Повторы из overlap окон дедуплицируются по исходному тексту/offsets.
  Совпадающие с dev тексты исключаются целиком; dev gold не участвует.
- Cosine top-16 по всей памяти, точный блочный поиск, temperature .1.
  Собственная группа исключается поиском; в этой dev-оценке её заранее нет в datastore.
- BIOES posterior преобразуется в голос нужного класса на начало/конец span.
  Для одного токена используется только `S`; для нескольких — геометрическое
  среднее start(B/S) и end(E/S). Это **адаптация kNN к GP**, не каноническая token-CE модель.
- Смешивание `(1−.2) GP + .2 memory`; пустая память не меняет исходную оценку.
  Затем тот же decoder усреднения окон и выбора непересекающихся spans.
  k/temperature/alpha фиксированы заранее, без поиска по dev.

Сохраняются datastore, BIOES labels, группы/hash исходных документов, provenance
checkpoint-а, исходные и изменённые предсказания. Отдельно измеряется inference latency:
память **может быть существенно медленнее**, пригодность к скоростному контракту пока не доказана.
Согласие памяти не означает, что dev gold ошибочен.

## Символьное уточнение

`models/char_boundary.py`, `training/char_features.py`, `training/char_pipeline.py`:

Frozen GP предлагает кандидатов; компактный char-CNN получает оригинальные символы,
контекстное представление token anchor, класс и сторону границы. Предсказывает одну
из девяти точных Unicode-позиций в радиусе ±4 символа. Алфавит строится только по train,
неизвестные символы получают UNK. Контекст вокруг радиуса — ещё 6 символов с каждой стороны.

На train цели — настоящие character offsets; token anchors слегка сдвигаются
на ±2 для устойчивости. Поэтому цель может лежать **внутри** токена.
До 100 000 boundary-примеров, пять эпох, batch 256, AdamW 1e-3;
encoder не обновляется. Inference не видит gold; изменения применяются при
confidence ≥.6. Невалидные границы откатываются, пересечения разрешает общий decoder.

Best char-head выбирается по исходному dev exact-F1; dev не используется в train loss.
Это dev-based selection, не независимая финальная оценка. Голова не умеет находить
сущности, отсутствующие среди кандидатов GP. Порог .6 не оптимизируется в этом опыте.
Скорость cached-head выводится отдельно от encoder/cache-pass: её нельзя выдавать
за полную скорость сервиса. Текущий исследовательский pipeline делает дополнительные
проходы для кеширования; оптимизация единого serving forward ещё не выполнена.

## Распределение compute

Измерена одинаковая capacity-проба s32: batch 8 × 512, BF16, два optimizer steps,
обычный AdamW, без checkpointing. Локально **0.915 с**, A100 **0.615 с**:
в этой короткой пробе A100 быстрее в **1.49 раза**, а не в 5–10 раз.
Это не end-to-end benchmark. Peak allocated локально ~11.12 GiB, reserved ~13.16 GiB;
с desktop workload batch 8 проверенно помещается. На одном GPU опыты не накладываются.

В первых полных эпохах s53 на A100 train занимает примерно **245–247 с**,
eval — около **44 с**. В отдельной capacity-пробе обе auxiliary-головы дали
1.31 с против 0.615 с для двух шагов GP: CRF-ветки требуют большего запаса времени.
Локальный MLM в начале проходит примерно 200–220 шагов за 25 с, всего 23 045 шагов.

Оценка при пяти эпохах и без сбоев/заполнения диска:

| Работа | Распределённо | Если всё последовательно на A100 |
|---|---|---|
| Семь end-to-end абляций | A100, ориентир 3–4.5 ч | Те же 3–4.5 ч |
| MELM → s42, затем s57/s58 | Локально параллельно, ориентир 2–3 ч | Дополнительно примерно 1–2 ч |
| Общее время до последних моделей | Около 3–4.5 ч | Около 4–6.5 ч |

Выбран параллельный вариант: вероятная экономия порядка часа, но точное время
зависит от числа прошедших MELM-фильтр копий, kNN latency и скорости CRF.
Перенос тяжёлых checkpoint-ов идёт фоном после run; возврат последнего может добавить
ещё ~28 минут после обучения. Локальный компьютер должен оставаться включённым.
Короткие GPU smoke выполнены отдельно и могли кратковременно влиять на throughput A100;
их F1 и время не являются результатами серии.

## Проверки и ограничения

Проверены CPU unit/интеграционные тесты целей, масок и градиентов, train/eval/resume
новых голов, совпадение CRF с прежней реализацией, точный top-k против dense поиска,
фон O/self exclusion, Unicode-границы, отсутствие gold в inference и сохранение head.
GPU smoke прошли обе auxiliary-головы вместе, MELM generation/filter и оба frozen workflow.
Тестовые каталоги изолированы в `/tmp`, в MLflow не публиковались.

Полный дополнительный preflight: **14 840 train-окон, 1 682 dev-окна**, ни одного
пересечения BIOES-целей между сущностями. Покрытие 13 новых research-модулей
по полной suite — **94%** (включая branch coverage). Ruff изменённых Python-файлов
и `git diff --check` проходят. Изолированные GPU smoke-логи и веса удалены;
их можно воспроизвести, реальные experiment runs не затронуты.

Полная workspace-suite после расширения тестов: **304 passed, 21 skipped**, но глобальное
coverage **82.57% при gate 90%**: проверка coverage не прошла. Это не полностью зелёный CI.
Пропуски включают отсутствующие необязательные UzTransliterator/ahocorasick и
неприменимые GP-цели для Biaffine; в workspace есть также независимые незавершённые
transliteration/curation-модули. Gate не понижен; новые ветки измерены отдельно, не вместо общего.

Широкий поиск на одном dev увеличивает риск выбора по шуму. 91+ — цель,
не обещанный результат; улучшения оцениваются по сохранённым exact predictions,
не по train loss и не по исправленному вручную gold.
