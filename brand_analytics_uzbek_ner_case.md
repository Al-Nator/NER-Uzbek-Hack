# Кейс: NER для узбекоязычных текстов

## Описание

### Продукт или процесс, к которому относится кейс

Brand Analytics автоматически собирает и анализирует сообщения из социальных медиа и СМИ. Один из этапов обработки текста — выделение именованных сущностей: организаций и брендов, людей и географических объектов. Результаты используются для построения аналитических отчётов по информационному полю клиента.

Сейчас такое выделение работает для русского и английского языков, но полноценного промышленного сервиса для узбекского языка нет. При этом узбекские тексты могут быть написаны как на латинице, так и на кириллице, содержать смешение языков и падежные формы сущностей.

Задача возникает на этапе автоматической обработки собранных сообщений. До агрегации данных и формирования клиентских отчётов необходимо найти сущности, определить их тип — `ORG`, `NAME` или `GEO`.

Для проекта уже подготовлены размеченные данные и базовое решение. Участникам предстоит улучшить качество выделения сущностей и реализовать воспроизводимый и возобновляемый пайплайн обучения, а также готовый к интеграции инференс-сервис.

## В чём боль и сколько она стоит бизнесу сейчас

Без качественного NER для узбекского языка Brand Analytics не может полноценно формировать отчёты по организациям, персонам и географическим объектам в узбекоязычном информационном поле.

Клиенты получают менее полную аналитику и вынуждены тратить больше времени на ручной поиск и анализ упоминаний значимых организаций, персон и географических объектов. Это снижает ценность продукта для клиентов, работающих с рынком Узбекистана, и ограничивает возможности развития Brand Analytics в этом сегменте.

## Кто пользователь решения и как он им пользуется

Основные пользователи — аналитики, PR-, маркетинговые и репутационные специалисты компаний, которые исследуют информационное поле Узбекистана в интерфейсе Brand Analytics.

Пользователь не взаимодействует с NER-сервисом напрямую. Сервис работает внутри конвейера обработки сообщений: автоматически находит в текстах организации, персон и географические объекты, после чего результаты агрегируются и отображаются в аналитических отчётах.

На основе этих отчётов пользователь может:

- определять основных участников информационного поля;
- видеть наиболее упоминаемые бренды, организации и персоны;
- обнаруживать конкурентов и значимых участников обсуждений;
- принимать решения по коммуникациям, маркетингу и управлению репутацией.

## Постановка задачи и этапы работы

Необходимо разработать решение для выделения именованных сущностей в узбекоязычных текстах социальных медиа и СМИ.

Решение должно:

- находить сущности трёх типов — `ORG`, `NAME` и `GEO`;
- определять их точные символьные границы в исходном тексте;
- работать с узбекской латиницей;
- работать с узбекской кириллицей;
- корректно обрабатывать смешанные русско-узбекские тексты.

### Этапы работы

1. **Исследовать данные:** проверить распределение классов, качество разметки и основные типы ошибок.
2. **Провести эксперименты** с моделями, архитектурами, гиперпараметрами и способами предобработки текста.
3. **Выбрать лучшее решение** по результатам проверки на предоставленной валидационной выборке.
4. **Обучить итоговую модель** и проанализировать Precision, Recall и F1 отдельно для классов `ORG`, `NAME` и `GEO`.
5. **Реализовать воспроизводимый пайплайн обучения:**
   - зафиксировать зависимости;
   - зафиксировать использованные данные;
   - указать версию базовой модели;
   - сохранить конфигурацию;
   - зафиксировать гиперпараметры;
   - зафиксировать `random seed`;
   - предоставить команды для повторного обучения модели;
   - предоставить команды для получения предсказаний на валидационной выборке;
   - предоставить команды для расчёта метрик, сопоставимых с заявленными.
6. **Реализовать инференс-сервис с HTTP API**, который принимает тексты сообщений и возвращает:
   - найденные сущности;
   - их типы;
   - символьные координаты.

   Сервис должен быть подготовлен к запуску в Docker.
7. **Подготовить документацию** по запуску, отчёт об экспериментах и разбор основных ошибок модели.

### Дополнительные задачи

После выполнения обязательной части команды могут реализовать дополнительные возможности:

- оценку производительности сервиса с указанием используемого оборудования и условий измерения:
  - скорость обработки;
  - задержка ответа;
  - потребление GPU-памяти;
- расширение обучающей выборки с использованием:
  - открытых данных;
  - синтетической генерации;
  - дополнительной автоматической разметки;
- нормализацию сущностей;
- демонстрационный интерфейс для ввода текста и визуализации найденных сущностей;
- дополнительную оптимизацию скорости инференса и потребления GPU-памяти.

> Дополнительные задачи оцениваются отдельно и не компенсируют отсутствие работающего API, воспроизводимого и возобновляемого обучения или обязательного формата ответа.

- обеспечивать промышленную нагрузку, отказоустойчивость, автоматическое масштабирование и заданный SLA.

## Описание данных

До начала хакатона участникам будет предоставлена ссылка на облачную папку, содержащую:

- обучающую и валидационную выборки;
- описание схемы данных и классов сущностей;
- минимальное базовое решение для обучения и инференса;
- описание HTTP API и пример ожидаемого ответа инференс-сервиса;
- скрипт и инструкцию для локального расчёта метрик.

Данные представляют собой тексты сообщений из социальных медиа и СМИ на узбекском языке.

В выборках присутствуют:

- короткие разговорные сообщения;
- длинные публикации;
- узбекская латиница;
- узбекская кириллица;
- смешанные русско-узбекские тексты.

### Классы сущностей

| Класс | Описание | Примеры |
|---|---|---|
| `ORG` | Организации, компании, бренды, государственные органы, банки, медиа и интернет-платформы | `Spendrups`, `Vazirlar Mahkamasi`, `Kun.uz`, `O'zbekiston Respublikasi Markaziy banki` |
| `NAME` | Имена, фамилии, полные имена и однозначные псевдонимы людей | `Shavkat Mirziyoyev`, `Islom Karimov`, `Komiljon Alimov` |
| `GEO` | Страны, регионы, города, районы, населённые пункты и именованные объекты с локационным значением | `Toshkent`, `O'zbekiston`, `Samarqand`, `Farg'ona viloyati` |

Подробные правила определения границ и разбора пограничных случаев входят в комплект материалов для участников.

### Подготовленные выборки

- **Обучающая выборка:** 13 000 размеченных текстов.
- **Валидационная выборка:** 1 500 размеченных текстов.
- **Закрытая тестовая выборка:** используется организаторами для итоговой оценки решений и участникам не предоставляется.

## Метрики

Качество выделения сущностей оценивается с помощью:

- Precision;
- Recall;
- F1.

Сущность считается найденной правильно только при одновременном совпадении:

1. идентификатора исходного текста;
2. типа сущности — `ORG`, `NAME` или `GEO`;
3. начальной символьной координаты;
4. конечной символьной координаты.

Используется **строгое сопоставление границ сущностей**.

Частичное совпадение границ или правильные границы при неправильном типе сущности не засчитываются.

Для всего набора сущностей рассчитываются:

- micro-Precision;
- micro-Recall;
- micro-F1.

Дополнительно Precision, Recall и F1 рассчитываются отдельно для классов:

- `ORG`;
- `NAME`;
- `GEO`.

Жёсткий минимальный порог качества не устанавливается.

К итоговой оценке допускаются решения, прошедшие техническую проверку API и Docker-контейнера.

Основная итоговая метрика на закрытой выборке — **exact-span micro-F1**, с дополнительным анализом Precision и Recall:

- в целом;
- отдельно для `ORG`;
- отдельно для `NAME`;
- отдельно для `GEO`.
