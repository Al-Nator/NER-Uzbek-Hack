# Uzbek NER — анализ текста

Frontend для существующего FastAPI backend. React 19, TypeScript, Vite; интерфейс
на русском языке, тексты на узбекской латинице и кириллице. Шрифты поставляются
в сборке, внешние CDN и другие внешние сервисы не используются.

## Разработка

Нужен Node.js 20.19+ или 22.12+. Из каталога `frontend/`:

```bash
npm ci
npm run dev
```

Откройте <http://localhost:5173>. Backend должен работать на
`http://127.0.0.1:8000`; команды запуска описаны
в [backend/README.md](../backend/README.md).

Для другого адреса backend скопируйте `.env.example` в `.env` и измените
`NER_API_TARGET`. Перезапустите Vite после изменения. Vite проксирует
`/api`, `/healthz`, `/livez`, `/docs` и `/openapi.json`:
добавлять CORS для стандартного запуска не требуется.

```bash
npm test
npm run build
npm run preview
```

`preview` также проксирует API, но предназначен для локальной проверки сборки.

## Docker

Из корня репозитория:

```bash
docker compose up --build
```

Frontend: <http://localhost:3000>. API доступен через тот же origin;
Swagger открывается по ссылке в интерфейсе.
Корневой Compose переиспользует настройки backend из
`backend/compose.yaml`; standalone-запуск backend остаётся доступен.

Frontend собирается отдельно и обслуживается непривилегированным Nginx.
Nginx ожидает backend под DNS-именем `backend:8000`. В frontend-образ включён
снимок текстов train/dev без эталонной разметки. Веса модели, backend и прочие
исследовательские артефакты в него не входят.

## Возможности

- Три режима: свой текст, случайный текст из датасета и файл.
- Пустое поле для своего текста; встроенных примеров нет.
- Все 13 000 текстов train и 1 500 текстов dev, выбор выборки и новый случайный текст.
- Пакетная загрузка TXT, JSON и JSONL с предварительным просмотром документов.
- Подсветка `NAME`, `ORG`, `GEO`, выбор сущностей, фильтры и развёрнутый просмотр.
- Просмотр и копирование JSON, экспорт **всего пакета** без изменения схемы API.
- Статус готовности модели, загрузка, отмена запроса и понятные ошибки.
- Адаптивная вёрстка, клавиатурная навигация, Ctrl / ⌘ + Enter, reduced motion.

JSON-файл должен содержать массив объектов:

```json
[
  { "hash": "document-001", "text": "Ali Toshkent shahrida ishlaydi." }
]
```

В JSONL каждый объект находится на отдельной строке. TXT — один документ;
его `hash` берётся из имени файла. Файлы должны быть в UTF-8. Поля, кроме
`hash` и `text`, не отправляются. Пустой текст в пакетном документе допустим.

Локальные ограничения соответствуют настройкам backend по умолчанию:
64 документа, 50 000 символов на текст, 500 000 символов на пакет. Размер
загружаемого файла — до 8 МБ. При изменении лимитов backend синхронизируйте
`LIMITS` и подписи интерфейса. Серверные ошибки, включая более строгие
лимиты, показываются отдельно; тексты не обрезаются.

Координаты `[start, end)` — Unicode code points Python. Frontend использует
`Array.from(text)`, корректно обрабатывает эмодзи, вложенные и пересекающиеся
сущности. Перед показом проверяет структуру ответа, порядок `hash`, метки,
границы и дубли. Исходный текст не нормализуется.

В приложении нет фиктивных предсказаний, аналитики или сохранения текстов
в localStorage/IndexedDB. После редактирования исходных данных старый результат
сбрасывается. Долгий запрос можно отменить; клиентский тайм-аут — 180 секунд.
Отмена прекращает ожидание в браузере, но не останавливает уже запущенный
инференс на сервере.

## Проверки

`npm test` проверяет Unicode-координаты, пересечения, загрузку файлов, лимиты,
контракт ответа, реальные формы HTTP-ошибок и отмену. Тестовые ответы существуют
только в тестах и не входят в production-сборку.

Браузерные регрессионные тесты проверяют отмену без повторной отправки формы,
сброс устаревших результатов, ошибку недоступности модели и мобильный интерфейс:

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты сами запускают Vite на порту 5174 и перехватывают запросы тестовыми
ответами. Рабочий backend и веса не нужны. `npm run format:check` проверяет
форматирование исходников; `npm run format` применяет его.

## Случайные тексты из датасетов

Исходные файлы: `ner_uz_hackathon_participant/data/train.jsonl` и `dev.jsonl`. В
`frontend/public/datasets/` подготовлен статический снимок всех 14 500 записей
с полями `hash` и `text`; эталонные `entities` исключены. Браузер получает каталог
и один фрагмент до 128 записей, а не весь корпус. Выбор равномерный по записям
выбранной выборки; непосредственно предыдущая запись не повторяется.

Снимок доступен с того же адреса, что frontend, включая Docker. Просмотр текстов
не требует запущенной модели; анализ по-прежнему использует `POST /api/v1/predict`.
Текст и hash передаются без изменений. Свой текст сохраняется при переключении
режимов. Новый текст, выборка или режим сбрасывают старые результаты анализа.

После обновления исходных JSONL пересоберите снимок:

```bash
npm run datasets:prepare
npm run build
```

Можно передать другой каталог с `train.jsonl` и `dev.jsonl`:
`npm run datasets:prepare -- /absolute/path/to/data`. Скрипт сохраняет SHA-256
источников и версии путей к фрагментам в `public/datasets/manifest.json`.
Снимок поставляется с исходниками frontend, поэтому отдельная Docker-сборка
не требует доступа к соседним каталогам. Для новых данных пересоберите образ.
